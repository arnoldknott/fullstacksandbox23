# Message `confidential` field: encrypted-at-rest plan

## Goal

Add one **new, independent, optional** field `confidential` (`Optional[str]`) to the
`Message` model. It is unrelated to the existing `content` field: a message may have
`content` and/or `confidential`, each independently optional.

- **Plaintext at the boundary:** the field is a plain `str` in the `Create`, `Read`,
  `Update`, and `Extended` schemas, transferred unencrypted through the REST
  (`/api/v1`) and Socket.IO (`/socketio/v1`) interfaces.
- **Encrypted at rest:** stored in PostgreSQL as an AES-256-GCM envelope in a `JSONB`
  column, using the existing [application encryption module](../../../backend/src/core/encryption.py).
- **Id-bound:** the encryption associated data binds the row, so ciphertext cannot be
  moved between records.

This is **encryption at rest only** — it protects database dumps, backups, replicas, and
direct database inspection. It is not end-to-end encryption: plaintext still crosses the
REST/Socket.IO transport (protected by Transport Layer Security) and exists transiently in
server memory, and must never be logged. See the
[application encryption contract](README.md#application-encryption) and the
[data-storage policy](README.md#data-storage-policy).

## JSON vs JSONB

- `JSON` stores the exact text (preserving whitespace, key order, and duplicate keys); it
  is reparsed on each access and cannot be indexed.
- `JSONB` stores a normalized binary form (deduplicated keys, insignificant whitespace
  dropped); it supports indexing and operators, with marginally slower writes and faster
  reads.

The envelope is opaque (never queried into), so either works. This plan uses **JSONB**,
the PostgreSQL default best practice.

## Design

A declarative `encrypt=True` flag on the model-factory `Attribute` marks the field. The
model factory maps the flag to a `JSONB` table column while keeping the API schemas as
`str`. `BaseCRUD` is the single encrypt/decrypt choke point for both the REST view and the
Socket.IO namespace, which both flow through it.

### Associated data

The encryption module's signature is `encryption.encrypt(location, purpose, value)`. The
`purpose` parameter is the shared contract's "canonical field/path purpose" (Redis callers
pass a JSON path there). For a database column the **field name** is the purpose, so the
CRUD passes each encrypted field's own name:

- `location = f"message:{id}"` (binds the ciphertext to the row)
- `purpose = "confidential"` (the field name, passed as the `purpose` argument)

The row `id` is generated by `default_factory=uuid4` and is available immediately after
`model_validate()` in `create()`, and is known in `update()`.

## Steps

1. **Factory flag** — [backend/src/models/base.py](../../../backend/src/models/base.py):
   add `encrypt: bool = False` to `Attribute`. In the `if table:` block of
   `create_model(...)`, for encrypted attributes give the **table column** a `JSONB` type
   (`Field(sa_column=Column(JSONB, nullable=True))`, annotation `Any`/`Optional[dict]`)
   while the `Create`/`Read`/`Update`/`Extended` schemas keep the declared `str`. Attach
   the set of encrypted field names to the table model as a class attribute
   (`__encrypted_fields__`) for the CRUD to discover. The field is included in `Extended`
   by default inheritance — it is not excluded.

2. **Model** — [backend/src/models/quiz.py](../../../backend/src/models/quiz.py): add
   `Attribute(name="confidential", type=Optional[str], field_value=None, encrypt=True)` to
   `Message`, leaving the existing `content` attribute untouched.

3. **CRUD integration** — [backend/src/crud/base.py](../../../backend/src/crud/base.py):
   read the encrypted field set in `__init__`.
   - `create()`: after `model_validate` (id known), for each encrypted field with a
     non-`None` plaintext value, call `encryption.encrypt(f"message:{id}", "confidential",
     plaintext)` and set the envelope before add/commit. A `None` value stays SQL `NULL`.
   - `update()`: encrypt the provided plaintext before setting it on the row.
   - `read()`: after fetching rows and after the access-log commit, **expunge the rows
     from the session** and then decrypt each encrypted envelope back to plaintext (skip
     `None`). This ensures the snapshot path (`extended_model.model_validate(entity)`) sees
     a `str`. Bad, tampered, or malformed envelopes fail closed (the module contract).

4. **Migration (dev only)** — the developer runs the dev migration script
   (`scripts/dev/postgres_migration_*.sh`) when the code is ready; it autogenerates the
   Alembic revision adding the nullable `confidential` `JSONB` column to the `message`
   table. Stage/production migration scripts are generated automatically by the GitHub
   Actions continuous-integration pipeline and are not created here. Tests need no
   migration (they use `SQLModel.metadata.create_all`).

## Key technical risk

In `BaseCRUD.read()`, the post-fetch `logging_crud.create_many(...)` commits the session.
If a decrypted plaintext were set on an **attached** ORM row, that flush could persist the
plaintext back into the `JSONB` column and silently defeat at-rest encryption. Mitigation:
**expunge the rows before decrypt-mutating** (`expire_on_commit=False` keeps loaded
attributes), so the plaintext is never flushed.

## Tests

- **Fixtures** — [backend/src/tests/utils_quiz.py](../../../backend/src/tests/utils_quiz.py):
  add `confidential` plaintext to some message create/update fixtures; keep some fixtures
  with only `content` and some with only `confidential` to prove independence.
- **REST** —
  [backend/src/routers/api/v1/tests/test_quiz.py](../../../backend/src/routers/api/v1/tests/test_quiz.py)
  (`TestMessage`): create/read return plaintext `confidential`; `content`-only and
  `confidential`-only messages both work; update re-encrypts; the field appears in the
  read/extended output.
- **At-rest assertion** — read the raw database row and assert the column is an envelope
  (`is_encryption_envelope(...)`), not plaintext; a tampered stored envelope makes `read()`
  fail closed.
- **Socket.IO** —
  [backend/src/routers/socketio/v1/tests/test_quiz_namespace.py](../../../backend/src/routers/socketio/v1/tests/test_quiz_namespace.py):
  message create/read over the namespace returns plaintext `confidential`.
- **Null path** — `confidential=None` stores SQL `NULL` and reads back `None`.
