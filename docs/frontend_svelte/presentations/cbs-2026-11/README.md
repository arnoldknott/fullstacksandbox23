# CBS presentation inputs

The [presenter controls](../../../../frontend_svelte/src/routes/%28layout%29/presentation/teachingengagement/cbs-2026-11/PresenterControls.svelte) publish the active input through the presentation's state question when `presenter=true` and the signed-in presenter has write or ownership access. The [mobile inputs page](../../../../frontend_svelte/src/routes/%28layout%29/presentation/teachingengagement/cbs-2026-11/inputs/+page.svelte) follows these changes through Socket.IO.

The interactive slide identifiers are `context-map` for places, `inspiration` for books, and `comments-and-questions` for comments. These mappings must match the identifiers generated by [FramedSlide](../../../../frontend_svelte/src/routes/%28layout%29/presentation/teachingengagement/cbs-2026-11/FramedSlide.svelte) from its `part` and optional `section` properties. Other slides leave the current input unchanged.

Reset is available on the welcome slide in presenter mode when an input is active and the presenter has write or ownership access. Reset clears the active input without deleting contributions.

## Returning after sign-in

The deck keeps its current slide and fragment in the URL hash. Automatic Socket.IO reauthentication preserves the complete browser URL, including `presenter=true` and the hash, so completing sign-in resumes that slide and fragment. The return target captures Reveal.js's live position even before its throttled hash update completes. Slide changes replace the hash without adding a browser-history entry for every slide.

Background requests return an authentication error instead of following sign-in redirects. Socket.IO ticket failures start one browser-level sign-in through the shared session lifecycle. Login links do not preload authorization transactions, and authentication routes skip provider-profile requests while credentials are being renewed.
